# 고객·관리자 화면 전체 확인표 (2026-09)

대상 브랜치: `codex/p0-customer-legal-ui`

이 문서는 개발자가 아닌 운영자도 Preview와 Supabase staging에서 10개 요구사항을 처음부터 끝까지 확인할 수 있게 만든 클릭 순서표다. 체크 항목은 실제 결과를 본 뒤에만 표시한다.

> 중요: 주문·결제·판매자·상품·재고·교환·반품처럼 데이터가 바뀌는 테스트는 Supabase staging ref `aeooyivfijthfcrfrnyk`에서만 한다. Production에서는 데이터 생성·수정·결제·환불을 하지 않는다.

## 시작 전에 준비할 것

- [ ] 배포 대상에 DB 마이그레이션 `0149`~`0160`이 적용되어 있다.
- [ ] `TEST_SUPABASE_PROJECT_REF`와 `SUPABASE_URL`의 프로젝트 ref가 모두 `aeooyivfijthfcrfrnyk`다.
- [ ] 관리자 계정과 일반 구매자 계정을 각각 준비했다.
- [ ] PC(약 1440px)와 모바일(390×844)에서 각각 확인한다.
- [ ] 아래 테스트용 판매자 2곳은 staging에만 등록한다. 실제 운영 공개 전에는 실사업자 자료로 교체한다.
- [ ] 같은 브랜드에 속하지만 판매자가 서로 다른, 가격이 있는 상품 2개를 준비한다.
- [ ] 주문제작 정책을 켠 상품 1개와 재고가 1개인 상품 1개를 준비한다.

테스트 진행 순서는 다음과 같다.

`관리자 판매자 등록 → 관리자 상품 연결·고시 입력 → 고객 상품목록·상세 → 장바구니 → 주문 동의 → 주문완료 → 관리자 판매자 수락 → 마이페이지 교환·반품 → 관리자 처리 → 마케팅 철회 → 재고 경합`

## 1. 통신판매중개 안내

- [ ] 홈페이지 추천상품 아래에 `통신판매중개 안내`가 보인다.
- [ ] 모든 페이지의 공통 푸터에 같은 안내가 보인다.
- [ ] 상품 상세, 장바구니, 주문서, 주문완료, 마이페이지 주문내역에 같은 안내가 보인다.
- [ ] 안내에 `통신판매의 당사자가 아닙니다`와 `백조 오브제가 부담하는 책임은 제외되지 않습니다`가 모두 있다.
- [ ] `이용약관에서 자세히 보기`를 누르면 `/terms`로 이동한다.
- [ ] 주문서와 마이페이지 주문 영역에서 실제 판매자 표시보다 알아보기 어렵게 숨겨져 있지 않다.
- [ ] 모바일에서 글자가 잘리거나 화면 밖으로 넘어가지 않는다.

## 2. 실제 판매자 등록·수정·고객 노출

관리자에서 `/admin/sellers`를 연다.

- [ ] `새 판매자 등록`을 눌러 고객 표시명, 상호, 대표자, 사업자등록번호, 통신판매업 신고번호, 고객센터, 사업장·반품지, 이메일, 배송비, 무료배송 기준, 출고 예정, 교환·반품 조건을 입력할 수 있다.
- [ ] 필수값을 비운 채 저장하면 저장되지 않고 안내가 표시된다.
- [ ] 상태를 `검증 완료`로 저장한 뒤 목록에 해당 상호와 번호가 보인다.
- [ ] 수정 버튼으로 연락처를 바꾸고 새로고침해도 수정값이 유지된다.
- [ ] 상품에 연결된 판매자를 삭제하려 하면 삭제가 차단되고 `판매 중지` 사용 안내가 나온다.

관리자에서 `/admin/products/new` 또는 상품 수정 화면을 연다.

- [ ] `실제 판매자`에서 방금 만든 판매자를 선택할 수 있다.
- [ ] `작성 중` 또는 `판매 중지` 판매자는 목록에 상태가 구분되어 보인다.
- [ ] 검증되지 않은 판매자를 연결한 상품은 공개 판매할 수 없다.
- [ ] 저장 후 다시 상품 수정 화면을 열었을 때 선택한 판매자가 유지된다.
- [ ] 고객 상품카드의 가격 가까이에 `실제 판매자 · 법적 상호`가 보인다.
- [ ] 상품 상세 가격 가까이에 실제 판매자 상호와 `정보 열기` 버튼이 보인다.
- [ ] `정보 열기`를 누르면 같은 화면에서 상호, 대표자, 사업자번호, 통신판매번호, 사업장, 고객센터, 배송·반품 정보가 펼쳐진다.
- [ ] 별도 판매자 정보 페이지로 이동하는 버튼이 보이지 않는다.
- [ ] 판매자나 상품고시가 준비되지 않은 기존 상품에는 `판매 준비 중`이 표시되고 장바구니·바로구매가 차단된다.

## 3. 브랜드 표현

- [ ] `/brands` 제목과 소개에 `큐레이션 브랜드`가 표시된다.
- [ ] `검증 브랜드 수`와 `안심하고 선택할 수 있는 안전성을 갖춘 브랜드`가 보이지 않는다.
- [ ] `공개 자료와 브랜드 제출 자료`를 바탕으로 살펴본다는 안내가 보인다.
- [ ] SAFETY 항목에는 표시·인증 자료와 사용상 주의사항을 확인한다는 표현이 보인다.
- [ ] PC와 모바일에서 브랜드 수와 설명이 겹치지 않는다.

## 4. BEST·SELECTED 큐레이션 안내

- [ ] BEST 상품카드에 `BEST`와 `자체 큐레이션 · 기준 보기`가 가까이 보인다.
- [ ] `기준 보기`를 누르면 `/audit`로 이동한다.
- [ ] `/audit`에서 브랜드 제출 자료와 공개 자료를 바탕으로 자체 기준에 따라 선정한다는 설명을 확인할 수 있다.
- [ ] 상품카드의 다른 부분을 누르면 상품 상세로 정상 이동한다.
- [ ] 모바일에서 배지와 안내 링크가 서로 가리지 않는다.

## 5. 케어가이드 의료 안내

`/concerns/tear`를 포함해 공개된 모든 `/concerns/[항목]` 페이지를 연다.

- [ ] 증상 설명 시작 부분에 `수의사의 진단·처방 또는 치료를 대신하지 않습니다`가 보인다.
- [ ] 관련 상품 추천 바로 앞에도 같은 안내가 보인다.
- [ ] 각 페이지에서 의료 안내가 총 2회 보인다.
- [ ] `증상이 지속되거나 악화되는 경우 수의사와 상담` 문구가 있다.
- [ ] 상품 추천이나 보험 안내가 밀리거나 겹치지 않는다.

## 6. 상품군별 필수정보

관리자 상품 등록 또는 수정 화면의 `상품군별 필수정보`를 확인한다.

- [ ] 상품군 선택지에 푸드·간식, 영양·건강관리, 케어·위생용품, 패션·산책용품, 펫로스·기록상품, 라이프·가구·장난감이 구분되어 있다.
- [ ] 상품군을 바꾸면 그 상품군에 맞는 입력항목이 나타난다.
- [ ] 필수 항목 하나를 비운 채 `공개`로 저장하면 저장이 차단되고 누락 안내가 나온다.
- [ ] 모든 필수값과 검증 완료 판매자를 입력하면 공개 저장할 수 있다.
- [ ] 저장 후 다시 수정 화면을 열어도 모든 입력값이 유지되고 수정할 수 있다.
- [ ] 상품 상세의 `상품정보제공고시`에 입력값이 항목별로 표시된다.
- [ ] 상세설명 이미지에만 정보가 있는 것이 아니라 구조화된 항목으로 표시된다.

## 7. 장바구니 판매자별 묶음과 금액

같은 브랜드이면서 실제 판매자가 다른 상품 2개를 장바구니에 담고 `/cart`를 연다.

- [ ] 판매자별로 별도 묶음이 생기고 각 묶음에 실제 판매자명이 보인다.
- [ ] 각 묶음에 `이 상품의 판매자는 …이며, 백조 오브제는 … 거래를 중개합니다` 안내가 보인다.
- [ ] 각 판매자 묶음에 상품금액, 배송비, 출고 예정, 교환·반품 조건이 표시된다.
- [ ] 같은 판매자의 상품 수량을 바꾸면 그 판매자의 상품금액만 바뀐다.
- [ ] 같은 브랜드라도 판매자가 다르면 배송비가 각각 계산된다.
- [ ] 전체 결제정보의 판매자별 배송비 합계와 최종 결제 예정금액을 직접 더한 값이 같다.
- [ ] 품절·재고부족·판매 준비 중 상품이 하나라도 있으면 `주문하기`가 차단된다.

## 10-1. 주문·결제와 판매자 수락 분리

- [ ] `/checkout`에서 상품을 실제 판매자별로 다시 구분해 보여준다.
- [ ] 판매자별 상품, 상품금액, 배송비가 장바구니와 같다.
- [ ] 아래 필수 동의를 하기 전에는 결제 버튼이 비활성화된다.
- [ ] staging 무통장입금으로 주문을 완료하면 `/order-complete`에 결제·입금 상태와 판매자별 `접수 대기`가 구분되어 표시된다.
- [ ] 관리자 `/admin/orders`에서 주문을 열면 `판매자별 주문 수락`이 보인다.
- [ ] 판매자 한 곳만 `판매자 수락`으로 바꾸고 메모를 저장할 수 있다.
- [ ] 구매자 마이페이지에서 해당 판매자만 `수락`, 다른 판매자는 `접수 대기`로 보인다.
- [ ] 주문이 최종 취소되거나 전액 환불되면 판매자 상태도 `묶음 취소`로 바뀐다.

## 10-2. 개인정보 제3자 제공 동의와 증적

- [ ] 주문서에서 판매자마다 별도 필수 체크박스가 있다.
- [ ] 각 항목에 제공받는 법적 상호, 제공 목적, 제공 항목, 보유 기간, 거부 결과가 보인다.
- [ ] 판매자 제공 동의와 `주문 전 확인` 이용약관 동의가 별도 체크박스다.
- [ ] 판매자 동의 하나를 빼면 결제할 수 없다.
- [ ] 주문 후 관리자 주문 상세에서 동의 종류, 대상, 버전, 동의 시각, 내용 해시를 확인할 수 있다.
- [ ] DB `orders.consent_records`에 동의 당시 문구·해시·시각·IP·브라우저 정보가 저장된다.
- [ ] 주문 후 상품이나 판매자 정보를 바꿔도 기존 주문의 동의 문구와 판매자 스냅샷은 바뀌지 않는다.

## 10-3. 마이페이지 실제 작동

- [ ] 주문내역에 주문 당시 실제 판매자명이 보인다.
- [ ] 허용 상태의 주문에서 `주문 취소 요청`을 누르면 확인창 후 `취소요청`으로 바뀐다.
- [ ] 결제완료 주문에서 판매자별 `교환 요청` 또는 `반품 요청`을 누르면 사유 입력 후 접수 상태가 보인다.
- [ ] 같은 종류의 요청이 처리 중일 때 중복 접수가 차단된다.
- [ ] 관리자 `/admin/order-requests`에서 `검토 중 → 승인/반려 → 완료`로 바꾸고 고객 표시 메모를 남길 수 있다.
- [ ] `접수 → 완료`처럼 단계를 건너뛰거나 `완료 → 검토 중`으로 되돌리는 선택지는 표시되지 않고 API에서도 차단된다.
- [ ] 구매자 화면을 새로고침하면 관리자 상태와 메모가 그대로 보인다.
- [ ] 회원정보 이름·연락처를 수정하고 새로고침해도 저장값이 유지된다.
- [ ] `마케팅 수신 동의`에서 이메일·문자를 모두 끄고 저장하면 철회 완료 안내가 보이고, 새로고침 후에도 꺼져 있다.
- [ ] 작성한 후기에서 조회·수정·삭제가 작동한다.
- [ ] 회원탈퇴 확인창에서 보존·삭제 안내가 보이고, staging 테스트 계정으로 탈퇴하면 즉시 로그아웃된다.

## 10-4. 주문제작 상품

관리자 상품 화면에서 `주문제작 상품`을 켠다.

- [ ] 제작 기간, 시안·제작 확인 방법, 수정 횟수, 수정 범위, 사진 이용 목적, 사진 보관 기간, 사진 파기 방법, 취소 제한을 모두 입력해야 공개할 수 있다.
- [ ] 저장 후 상품 상세의 주문제작 안내에 위 내용이 모두 보인다.
- [ ] 주문서에 해당 상품만을 대상으로 한 별도 필수 동의가 나타난다.
- [ ] 주문제작 동의를 빼면 결제할 수 없다.
- [ ] 주문 후 관리자 주문 상세의 동의 증적에 `made_to_order` 기록과 당시 문구·시각이 보인다.

## 10-5. 재고 일치와 초과판매 방지

- [ ] 관리자에서 재고를 0으로 바꾸면 상품카드와 상세가 모두 품절 또는 구매불가로 바뀐다.
- [ ] 품절 상품 상세에서 장바구니와 바로구매 버튼이 비활성화된다.
- [ ] 상품을 담은 뒤 관리자가 재고를 0으로 바꾸면 장바구니에서 재고부족 안내가 나오고 주문이 차단된다.
- [ ] 재고 1개인 같은 상품을 구매자 브라우저 2개에서 동시에 주문한다.
- [ ] 먼저 완료된 주문 한 건만 생성되고, 나중 요청은 재고부족으로 실패한다.
- [ ] 실패한 요청에 빈 주문이나 음수 재고가 남지 않는다.
- [ ] 주문 취소·전액 환불의 기존 재고 복원 흐름도 한 번만 반영된다.

## 자동검사와 수동검사의 완료 기준

- 코드·문구·순수 계산 검사는 `npm run lint`, `npx tsc --noEmit`, `npx playwright test --project=products --project=admin --project=tracking --project=security`, `npm run build`가 모두 통과해야 한다.
- 전체 마이그레이션과 핵심 DB 상태 전이는 일회용 로컬 Supabase PostgreSQL에서 먼저 검증하되, 이 결과를 staging 로그인·주문·결제 검증의 대체로 보지 않는다.
- 주문·재고·관리자 CRUD·판매자 수락·교환·반품·마케팅 설정은 staging 쓰기 테스트가 통과해야 완료다.
- 카드결제, 취소, 부분환불, 전액환불은 Toss staging 승인 결과와 DB 재고·환불 원장을 다시 읽어 확인해야 완료다.
- 테스트가 환경변수 부족으로 `skip`되면 성공으로 표시하지 않는다.
- Production은 읽기 전용 화면 확인만 허용한다.

## 운영 공개 전에 반드시 넣을 실제 자료

- [ ] 각 입점 판매자의 법적 상호, 대표자, 사업자등록번호, 통신판매업 신고번호
- [ ] 사업장·반품지 주소, 고객센터 전화·이메일
- [ ] 각 상품의 정확한 상품정보제공고시 원문
- [ ] 판매자별 배송비·무료배송 기준·출고 예정·교환반품 조건
- [ ] 주문제작 상품별 실제 제작·시안·사진 보관 및 파기 정책
- [ ] 기존 공개 상품에 판매자와 상품고시를 연결하는 데이터 이관 결과

이 자료가 없는 상품은 임의 정보로 공개하지 않고 `판매 준비 중` 상태로 둔다.
