# 모바일 공통 디자인 및 로그인 전체 화면 — 2026-09-22

## 반영 내용

- 공통 한글 폰트의 자기 참조를 제거하고 Pretendard 계열을 적용했다. Next 글꼴 변수와 테마용 serif 변수도 분리했다.
- 기존 컨테이너에 공통 좌우 여백 토큰을 적용했다. 모바일 20px, 640px 이상 24px, 1024px 이상 32px, 1280px 이상 48px이다.
- 공통 섹션 간격은 모바일 48px / 태블릿 64px / 큰 화면 80px이다. 모바일에서 간격을 강제로 늘리던 임의 클래스 덮어쓰기를 제거했다.
- PageIntro·본문·정책 문서·입력 폼·상품/브랜드/케어/후기 카드의 읽기 크기를 정리했다. 모바일 입력 필드는 최소 16px이며, 상품 카드 설명은 14px로 읽을 수 있다.
- 작은 상품 목록은 480px 미만에서 한 열, 그 이상에서 기존 다열 구조다. 추천 상품은 가로 레일 안에서 읽을 수 있는 카드 폭을 확보했다.
- 상품명·상품 설명·판매자·브랜드/케어 카드 문구에 붙어 있던 말줄임을 해제했다. 데이터, 본문 및 기능을 삭제하지 않았다.
- 로그인은 최대 폭 카드와 외곽 여백, 세이지색 왼쪽 배경을 제거했다. 데스크톱에서는 화면 전체를 사진/폼 두 열로 사용한다. 모바일은 폼, 전체 사진, 기존 소개 문구 순서다.
- 기존 BrandMark를 홈과 같은 CMS 로고에 연결했다. 집중형 헤더와 로그인·비밀번호 찾기·인증 등에서 공유한다.
- About/B2B/Audit은 모바일에서 텍스트 다음에 이미지 전체를 원본 비율로 표시한다. 회사소개 원문은 그대로 유지했다.
- 앞서 추가한 /about의 관리자 화면 연결표 및 공개 스모크 앵커 누락도 보완했다. 소개 본문은 코드 관리임을 명시하고 메뉴 관리 화면만 연결했다.

## 검증 결과

- 공개 화면 23종 × 320/390/768px = 69회: 정상 응답, 가로 넘침 없음, 처리되지 않은 브라우저 오류 없음. 변경 전 390px 문구와 비교하여 기존 본문 누락 없음.
- 공지 상세는 로컬 공개 데이터가 없어 표본 방문을 못 했다. 토큰·주문 쿼리가 없는 인증/완료 페이지는 해당 초기 상태만 확인했다. 비공개 기능 플래그는 유지했다.
- 관리자: 실제 로컬 로그인 후 /api/members/me에서 admin/active 확인. 인증 외 쓰기 요청을 차단하고 메뉴·포커스·선택 상태와 상품 목록 및 추가 21개 화면을 390px에서 점검했다. 저장·삭제·결제는 수행하지 않았다.
- 새 브라우저 회귀 7개 통과: 로그인 320/390/768/1440px의 전체 폭, 홈 로고 일치, 소개 문구/로그인 기능 보존, 모바일 폼 입력 크기, About/B2B/Audit 모바일 사진 비율과 데스크톱 문구 동일성.
- 기존 모바일 회귀: 공개 화면과 상품 카드 버튼 14개 통과. 회원 전용 3개는 로컬 인증 환경 문제로 실패했다. 서버 로그에 members.session_version 컬럼 누락 및 JWTSessionError가 확인되었으며, 별도 실제 회원 로그인도 완료되지 않았다. 회원 전용 화면의 실검증 완료로 간주하지 않는다. 이 디자인 작업에서 DB를 변경하지 않았다.
- products/admin/tracking/security 계약 검사: 최초 1,217개 통과, 기존 /about 관리표 누락 1개 실패. 누락 수정 후 해당 관리표 검사 7개 모두 통과했다.

## 로컬 증거

### 마이페이지 연결 오류 후속 확인

- 실제 연결 오류는 `.env.local`의 `AUTH_URL`이 개발서버(3000)와 다른 3001 포트를 가리켜 발생했다. `/mypage`의 307 응답이 실행 중이지 않은 3001의 로그인으로 이동하는 것을 재현했다.
- 로컬 인증 주소를 `http://localhost:3000`으로 수정하고 Next 개발서버의 환경변수 자동 재적용을 확인했다. DB와 세션 검증 코드는 변경하지 않았다.
- 390px 하단 마이 메뉴와 1440px 상단 마이페이지 버튼 모두 동일한 3000 포트의 로그인 화면으로 정상 이동했다. 주문 탭 쿼리도 로그인 복귀 주소에 보존된다.
- 별도 브라우저 컨텍스트에서 실제 일반회원 및 관리자 로그인을 수행하고 `/api/members/me`의 `user/active`, `admin/active`를 각각 확인했다. 두 계정 모두 `/mypage` 요약 화면이 열리고 처리되지 않은 브라우저 오류가 없었다.
- 이전 로그의 session_version 누락 경고는 기존 레거시 조회 폴백 대상이며, 이번 연결 오류의 직접 원인은 아니었다. 위 3개 모의 세션 모바일 회귀 테스트 전체를 재검증한 것은 아니다.
