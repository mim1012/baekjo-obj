# 홈페이지 전체 화면 ↔ 관리자 실제 연결 보고서

작성일: 2026-09-01

판정 기준: 현재 고객 홈페이지의 실제 화면과 실제 데이터 조회 코드

제외 범위: 보험 화면과 보험 운영 기능은 별도 메뉴로 유지

## 1. 최종 판정

DB 적용 전 코드 기준으로 다음 구조까지 정리했다.

- 보험과 화면 없는 로그인 콜백을 제외한 고객 화면 29개와 모든 화면 공통 영역 1개를 `전체 화면 관리`에 등록했다.
- 각 고객 화면 카드에는 실제 주소, 직원이 바꿀 수 있는 내용, 관리 버튼, 가능한 작업, 고객 반영 방식을 함께 표시한다.
- 고객 화면에서 읽지 않는 관리자 입력칸은 제거했다. 예전 DB 값은 삭제하지 않고 관리자 수정 payload에서 제외해 안전하게 보존한다.
- 같은 값을 여러 화면에서 바꾸던 중복을 제거했다. 상품 진열 상태와 기존 브랜드 수정은 각각 한 화면만 정본으로 사용한다.
- 맞춤 진단은 질문·답변·결과 조건·추천 연결·결과 화면 공통 문구가 한 흐름으로 이어지게 수정했다.
- 배송비·무료배송 기준과 무통장입금 자동취소를 서로 다른 설정으로 분리했다.
- 화면과 실제 데이터가 없던 관리자 페이지 3개는 메뉴만 숨기지 않고 페이지·API·관련 코드까지 제거했다.

아직 “운영에서 완전히 사용 가능” 판정은 아니다. 새 CMS와 상품 태그 저장용 마이그레이션 `0148`~`0153`을 staging DB에 적용하고 실제 등록·수정·삭제·게시를 확인해야 한다. 현재 로컬 환경은 Production DB를 가리키므로 운영 데이터 보호 규칙에 따라 DB 쓰기 검사는 실행하지 않았다.

## 2. 첫 직원이 사용하는 시작 순서

```text
관리자 로그인
  → 전체 화면 관리
  → 바꾸려는 고객 화면 이름 또는 주소 검색
  → 고객 화면 보기로 실제 위치 확인
  → 같은 카드의 관리하기 선택
  → 저장 방식 확인
      페이지 문구·이미지: 임시저장 → 게시
      상품·브랜드·목록 데이터: 저장 즉시 반영
      주문·회원·문의: 고객이 만든 기록을 상태·답변으로 처리
  → 고객 화면에서 결과 확인
```

직원이 상품 ID, 브랜드 ID, 질문 코드, 답변 코드를 직접 입력하지 않게 했다. 화면 안에서 이름을 검색하거나 한글 선택지를 고른다. 메뉴와 주요 입력칸 옆에는 실제 반영 위치를 설명한다.

상품 카드 태그의 흐름은 한 방향이다.

```text
상품 태그에서 “피부” 등록·이름 수정·노출·순서 설정
  → 상품 수정에서 “피부” 선택
  → 상품의 concernTags에 태그 코드 저장
  → 홈·스토어·브랜드 상품 카드가 같은 설정의 표시 이름을 읽음
  → 스토어 고민 필터도 같은 설정에서 허용된 태그만 표시
```

## 6. 맞춤 진단 연결 흐름

이전에는 관리자가 질문을 추가해도 결과 계산은 `q2`, `q3`만 읽어 새 질문이 결과에 연결되지 않았다. 현재 흐름은 다음과 같다.

```text
관리자가 질문과 한글 답변 작성
  → 내부 답변 코드는 자동 생성되어 직원에게 숨김
  → 선택지의 위·아래 버튼으로 고객 표시 순서 변경
  → 결과 규칙에서 “고객이 답한 질문” 선택
  → “이 답을 골랐을 때” 선택
  → 결과 제목·설명·상품·브랜드·보험·키트 안내 선택
  → 저장 전 삭제된 질문·답 참조 검사
  → 고객 답변 계산이 같은 질문·답 조건을 읽음
  → /diagnosis/result가 같은 결과와 공통 문구를 표시
```

기존 DB의 `q2`, `q3` 규칙도 계속 동작하도록 호환 처리를 유지했다. 공개 화면의 현재 기본 문구는 그대로 두고 관리자 저장값이 있을 때만 게시된 값을 읽는다.

## 7. 제거한 중복·미연결 입력

아래 항목은 현재 고객 화면에서 읽지 않으므로 관리자에서 제거했다.

| 제거한 관리자 입력 | 제거 이유 | 현재 사용 위치 |
|---|---|---|
| 고민의 가능한 원인 | 고객 고민 상세에서 사용하지 않음 | 없음; 기존 DB 값만 보존 |
| 고민의 추천 브랜드 | 고객 고민 상세에서 브랜드 목록을 읽지 않음 | 추천 상품만 `/admin/concerns`에서 연결 |
| 고민의 보험 안내 문구 | 고객 고민 상세에서 사용하지 않음 | 보험은 별도, 진단 결과 안내는 `/admin/survey` |
| 상품 검증 포인트 | 현재 상품 상세에서 렌더하지 않음 | 없음; 기존 DB 값만 보존 |
| 상품의 예전 고민 연결 `relatedConcernSlugs` | 실제 상품 카드·관련 상품은 `concernTags`를 읽음 | 상품 카드 태그만 유지 |
| 상품의 검색용 일반 태그 | 현재 고객 화면 소비처 없음 | 상품 카드 태그만 유지 |
| 상품 성분·사용법·주의사항 | 현재 상품 상세 화면에서 렌더하지 않음 | 상세 본문 블록에서 필요한 공개 내용을 작성 |
| 브랜드 공식몰 주소 | 현재 브랜드 화면에 공식몰 버튼 없음 | 없음; 기존 DB 값만 보존 |
| 브랜드 근거 자료 주소 | 현재 고객 화면에서 링크를 표시하지 않음 | 공개 Audit 내용만 유지 |

중복 정본도 한 곳으로 통일했다.

- 상품의 `스토어 노출`, `추천`, `베스트`는 `/admin/products/display`에서만 바꾼다.
- 기존 브랜드의 내용·노출·추천·순서는 `/admin/brands/[id]`의 `전체 수정`에서만 바꾼다.
- 상품 카드 태그 정의는 `/admin/products/tags`, 상품별 선택은 `/admin/products/[id]`로 역할을 나눈다.
- 브랜드 배송비는 `/admin/brands`, 무통장 자동취소는 `/admin/order-policy`, 고객 안내 문서는 `/admin/pages/refund-policy`로 분리한다.

## 10. 첫 직원 교육 완료 기준

아래 다섯 가지를 한 번 실습하면 일상 운영이 가능하도록 화면을 구성했다.

1. `전체 화면 관리`에서 고객 화면 이름으로 관리 위치 찾기
2. 상품 하나를 수정하고 연결된 고객 화면 확인하기
3. 상품 카드 태그와 고민·케어 가이드의 차이 설명하기
4. 임시저장·게시와 저장 즉시 반영의 차이 설명하기
5. 삭제 대신 숨김이나 상태 처리를 사용해야 하는 데이터 구분하기

각 메뉴 아래에는 관리 범위가 한 줄로 표시된다. 등록·수정 창에는 연결 고객 화면 설명이 있고, 모호한 가격·재고·배송·순서·회원 상태·송장 필드에는 바로 옆 설명이 표시된다.

## 11. 검증과 DB 적용 전 남은 일

코드 단계에서 확인하는 항목:

- 모든 고객 `page.tsx`가 전체 화면 관리에 정확히 한 번 등록됐는지
- 모든 관리 버튼이 실제 관리자 페이지로 열리는지
- 고객 목록·상세 데이터에 등록·수정·삭제 경로가 있는지
- CMS 관리 버튼과 실제 페이지 정의가 1:1인지
- 상품 진열·브랜드 수정처럼 단일 정본이 유지되는지
- 맞춤 진단 질문·답·결과·공통 문구가 고객 결과까지 이어지는지
- 제거한 입력칸이 payload로 다시 전송되지 않는지
- TypeScript, lint, production build, DB 없는 관리자·상품 회귀검사

2026-09-01 최신 `mim/main` 통합 후 실행 결과:

- TypeScript 검사 통과
- 관리자·상품 DB 없는 회귀검사 678개 통과(스토어 필터 전체 관리, 적립금 기능 부재, 상품 화면 내 태그 등록, 고객 화면별 상품 진열 순서 계약 포함)

## 12. 완료 판정

아래 조건을 모두 만족해야 운영 완료다.

- 새 직원이 `전체 화면 관리`만 보고 수정 위치를 찾는다.
- 등록·수정 화면에서 고객 반영 위치를 확인할 수 있다.
- 저장 후 새로고침해도 값이 남고 같은 고객 화면에서 확인된다.
- 게시형 화면은 임시저장만으로 고객에게 노출되지 않는다.
- 삭제하면 안 되는 주문·회원 이력은 상태 처리로 보호된다.
- 고객 화면에서 읽지 않는 관리자 입력과 가짜 관리 화면이 없다.
- 같은 설정을 여러 관리자 화면에서 서로 다르게 바꿀 수 없다.
- staging 실사용 CRUD와 공개 화면 read-back이 전부 통과한다.
