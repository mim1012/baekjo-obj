# 주문·인증·환불·회원 조회 리뷰 수정

기준: develop 9bff314bc38d42b0c4ec6de57426aeb55e135866.

## 변경

- 주문 저장과 재고 차감을 `reserve_order` RPC 한 트랜잭션으로 묶는다. 재고 부족이나 주문 INSERT 실패는 모두 롤백한다. 응답이 불명확한 경우 주문을 보상 삭제하지 않는다.
- 비밀번호 해시 변경 시 DB trigger가 `session_version`을 증가시킨다. 로그인 시 JWT에 버전을 담고 이후 API와 페이지 인증에서 현재 DB 버전과 비교한다. 클라이언트 session.update는 버전을 갱신할 수 없다.
- 환불 payload 검증과 현재 주문의 환불 가능 여부 검증을 분리한다. 동일한 성공 요청의 재전송은 완료 기록을 반환하며 변경된 payload는 409로 거부한다.
- 회원 목록의 검색·필터·페이지·전체 집계를 서버에서 계산한다. 검색어는 SQL 인자로 전달해 %, 쉼표, 괄호도 문자 그대로 검색한다. 회원 상세는 ID로 직접 조회한다.

## 적용 순서와 영향

1. 기존 마이그레이션 실행 절차로 staging에 0151, 0152, 0153을 순서대로 적용한다.
2. 이 코드의 staging/Preview 배포에서 결제·인증·회원 CRUD를 검증한다.
3. 통합 검증 후 develop 릴리스 절차를 따른다.

새 코드에는 신규 컬럼과 RPC가 필요하므로 DB 마이그레이션을 먼저 적용해야 한다.
0152 배포 후 이전 버전 JWT는 다시 로그인해야 한다. 비밀번호 변경·재설정은 모든 기존 세션을 무효화한다.
코드 롤백 시 가산 컬럼/RPC/trigger를 삭제할 필요는 없지만, 구버전 코드는 세션 버전 검사를 하지 않으므로 세션 폐기 보장은 유지되지 않는다.
이 PR은 기존 불일치 주문·재고를 자동 수정하지 않으며, 별개의 주문 생성 요청을 동일 주문으로 묶는 멱등 키 계약은 추가하지 않는다.

## 검증

- lint: 오류 0, 기존 경고 30.
- TypeScript: 통과.
- production build: 통과 (운영 배포는 수행하지 않음).
- products/admin/tracking/security: 766 통과, skip 0.
- payments/shipments: 로컬·순수 테스트 53 통과. staging 설정 부재로 통합 테스트 43 skip — 통합 게이트 통과로 간주하지 않음.
- 신규 embedded PostgreSQL 테스트는 자격 증명 없이 메모리 안에서 실제 migration RPC를 실행한다. 주문·재고의 동시 롤백, 재고 한도, 비밀번호 변경 trigger, 502명 중 오래된 회원 검색·전체 집계, RPC 권한을 검증한다. 이는 운영 Supabase의 동시 연결·RLS·실제 배포 검증을 대체하지 않는다.
- 실제 환불 handler의 외부 I/O를 대체해 전액환불 replay/충돌/신규 요청 거부를 검증한다.
- 실제 JWT callback을 실행해 이전 세션, 새로운 로그인, legacy token, 정지 회원, 위조 session.update를 검증한다.

## 남은 staging 게이트

- 다중 브랜드 카드 승인·무통장입금, 재고 read-back, 취소·부분/전액환불과 원장 read-back.
- 이전 로그인 cookie의 읽기·쓰기 거부 및 새 비밀번호 로그인. golden 비밀번호 변경 테스트에 이를 추가했다.
- 회원 검색·페이지 이동·상세 직접 접근·승인 후 재조회, 실제 OAuth.
- Production/운영 DB에는 변경을 적용하지 않았다.
