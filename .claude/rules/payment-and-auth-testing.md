# 인증·주문·결제 테스트 규칙

## 인증

- 관리자와 구매자는 별도 브라우저 컨텍스트로 테스트한다.
- 로그인 직후 `/api/members/me`를 읽어 role과 status를 확인한다.
- 일반 회원가입은 이메일 인증 상태를 확인한다.
- 카카오·네이버는 callback 계약 테스트와 실제 OAuth 수동 테스트를 분리한다.

## 주문·결제

- 최소 2개 브랜드 상품을 포함한 주문을 사용한다.
- Toss 승인 전후 `payment_status`, `order_status`, 재고를 기록한다.
- 무통장입금은 `입금대기` 주문 생성과 관리자 입금확인을 별도 검증한다.
- 부분환불은 선택 수량·금액·잔여 수량을 검증한다.
- 전액환불은 환불 원장과 최종 상태를 검증한다.
- 각 시나리오 종료 후 staging 테스트 데이터의 정리 여부를 확인한다.

## 배송·Cron

- 배송은 브랜드별 송장과 배송 상태를 read-back한다.
- SweetTracker는 실제 API와 mock 계약을 구분해 결과를 기록한다.
- Cron 무인증 요청은 `401`, 인증 요청은 처리 결과 JSON을 확인한다.
- `failed` 또는 `dead`가 발생하면 후속 시나리오를 중단하고 원인을 기록한다.
